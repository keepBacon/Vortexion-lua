# Vortexion R2.6 — BloxStrike 启动稳定性专项

## 已知事实与未证实项
- 用户报告 BloxStrike 在 Android 上闪退，**没有提供该游戏的原始客户端崩溃日志**。因此当前不能断定哪个调用触发了进程退出。
- 审计现有 `src/BloxStrikeCore.luau`，确认首次初始化时会主动调用 Cloak `Start()`，而 Cloak 实际执行全局 `hookmetamethod(game, "__namecall", ...)`；这个调用无法通过普通 `pcall` 保证宿主进程不崩溃。
- `src/BloxStrikeBullet.luau` 的旧实现只要开启子弹追踪就同时尝试安装 Hitscan 与 Remote Hook，即使用户实际只想使用预测模式；这是独立的生命周期/模式选择缺陷。
- 皮肤分类创建、视觉 Heartbeat 和外观 RenderStepped 都在入口加载阶段注册，存在启动工作尖峰和不必要的空闲计算。

## 源码修改
1. **默认不安装 Cloak 全局 Hook**。`Cloak.Protect()` 仍作为兼容接口保留，但 R2.6 默认**不承诺**隐藏实例、绕过检测或全局枚举过滤。WindUI、皮肤和高亮仍按普通本地对象工作。
2. **窗口创建前后加错误隔离**：`CreateWindow` 异常时设置 `VortexionBootError`，回收桥接，不再让剩余子模块在空窗口上继续初始化。
3. **关闭功能时零战斗/子弹更新**：增加 `Combat:IsActive()`、`Bullet:IsActive()`；默认不扫描候选和投射物；按原开关重新启用。
4. **子弹追踪默认安全模式**：`LeadOnly` 不做 Hook；移动端 `Auto` 不主动安装函数与全局方法 Hook。明确选择高级路径时才进入对应实现（高级模式在某些执行器上仍可能不安全）。切换模式时先 Stop 再按需要 Start。
5. **视觉空闲快速返回**：ESP、移动和飞行全部关闭时不进行视觉间隔查询/场景检查。
6. **皮肤/UI 负载控制**：初始延迟 3 秒，按每 2 个分类让出一帧；自动最多创建 24 项，手动刷新一次最多 64 项。超过限制的分类需要后续做分页式列表，当前不保证显示所有分类。
7. **外观空闲快速返回**：没有模型、音效、动画和拖尾时不触发相机与音效更新。
8. 当前完整交付还包含尚未推送的 **R2.5 Forsaken 精简与 AOTR 战斗降风险**。

## 验收边界
- Python 构建重新生成 6 个旧单包 + 6 个模块化产物，逐一核对大小及 SHA-256。
- `tests/test_r26_blox_stability.py` 使用 Lua 5.4 Mock 验证默认不安装 Cloak Hook、默认渲染无战斗/子弹更新、激活后触发更新、卸载解绑。
- R2.5 / R2.4 / R2.3 专项回归继续保留。
- **未经 Roblox Android 真机与特定执行器崩溃日志确认，不能声明闪退已经彻底解决。** 设备侧需测试：仅进入 BloxStrike 打开 UI、关闭所有功能 1 分钟、单独启用视觉/FOV/皮肤，然后单独验证武器高级选项。

## 回归与使用注意
- UI 会保留现有功能，但取消了自动安装的全局 Cloak Hook。若有特定游戏功能依赖隐藏实例/注入 Hook，这部分能力将降级。
- 新 Loader 应显示 `2.6.0-blox-startup-guard`，运行时清单应包含 `r2.6`。
- 若依旧是直接关闭 Roblox 进程且没有 Luau 错误日志，请保存执行器名称与版本、Android 版本、设备型号、进入游戏后多长时间退出；这可以判断是否是原生崩溃，而非脚本抛错。
