# Vortexion R2.7 — 跨游戏失效第一轮底层修复

## 已确认的代码根因

1. `src/AOTRCommon.luau`、`src/SCPCore.luau`、`src/BloxStrikeCore.luau` 对 `Xeno`、`Velocity`、`LX63` 执行器名称做硬黑名单并在初始化前 `return`。这些名称不足以代表实际 API 能力，会直接禁用该游戏的整个入口。R2.7 改为仅记录执行器名称，按具体 API 能力决定功能是否可用。
2. R2.5 的 `ForsakenCore.luau` 本来就只打包八个控件，四个旧功能工厂已从活动构建移除。这是此前主动删减造成的功能缺失，**不是本轮已经恢复的功能**。
3. Loader 把 `BootStatus == partial` 当作整套脚本失败，掩盖已创建窗口与可用部分功能。R2.7 以可见的「部分功能初始化失败」状态保留诊断，不把它伪装成全功能通过。

## 新增共享输入链路诊断

到 UI → 调试 → 「触控回调自检（手动切换）」，实际触摸该开关，再点「显示触控回调自检」或「复制诊断」。
- 如果「原生控件事件」增加，并且「业务回调调用」增加：原生控件到桥接回调链路基本可用，需要进一步检查单游戏模块。
- 如果原生事件没有增加：优先检查执行器触摸事件、WindUI 事件绑定、屏幕遮挡和失效窗口。
- 「丢弃过期事件」增加说明事件回调与 Native 状态出现异步不一致；需要结合实际点击顺序定位。
这些计数是诊断手段，不等于某个战斗功能已经生效。

## 本次未解决的事项

- Forsaken R2.5 已删除的角色、战斗和外部功能并没有被直接恢复（恢复前需重新验证版本适配和副作用）。
- 其他游戏依赖的服务端远程、实体名称、碰撞和反作弊兼容没有安卓实测证据，本轮不虚报为已修复。
- `tests/test_wind_adapter.luau` 需要完整 WindUI 运行环境；本轮专项使用 Lua 5.4 mock 和静态构建检查，非安卓真机。

## 本地验证

- 36 项所选 Python/Lua 模拟回归通过（R2.7、R2.6、R2.5、R2.4、R2.3、启动异常与 R2 较新回归）；已修订两处仅限定旧版本字符串的测试，以及一个要求已移除危险 Hook 的历史断言。
- 6 个模块化 + 6 个独立 Lua 构建产物重新生成，`verify_release.py` 校验通过。
- GitHub `main` 远程基线：`ff00c42af1d1bb590ae4ee40aa7263a988748c3c`。部署脚本检查 SHA，不强推。

## 验收方式

1. 部署本次包并确认脚本结束显示 `R2.7 SUCCESS`。
2. 在游戏中运行统一 `loader.lua`，确认版本 `2.7.0-feature-health`。
3. 先在 UI → 调试 手动切换「触控回调自检」，点击「显示触控回调自检」。
4. 若事件正常，再分别验证 Forsaken FOV / AOTR FOV / BloxStrike 皮肤分类 / SCP 可见性测试，结合各模块状态检查具体失败路径。
5. 若仍然失效，请复制完整「原生控件事件」「业务回调调用」「最近异常」「执行器」和游戏 PlaceId；必要时上传执行器控制台日志。
