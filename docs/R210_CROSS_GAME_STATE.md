# Vortexion R2.10 · 跨游戏状态一致性修复

## 实际改动

- **共享 WindUI**：当原生控件回调早于最终状态写入时，延迟复核；所有游戏共用一个低频 1 Hz 状态核对器。仅核对 Toggle，不干扰输入、滑块拖动和下拉框刷新。
- **诊断**：新增「跨游戏回调状态复核」「查看游戏功能健康状态」以及原生事件/延迟修复/低频修复计数。现在可以区分控件 UI 值与业务值。
- **Forsaken**：死亡/观战时用相机位置计算高亮距离；角色切换不清除用户启用的功能；一秒核对游戏状态、UI 和桥接值；角色变化自动清理旧标记并重建。
- **AOTR 大厅**：注册大厅角色、相机、FOV 状态诊断。
- **AOTR 战斗**：注册 Titans/Combat/Movement/ESP/Farm 模块初始化状态和错误数量诊断。
- **BloxStrike**：模块失败的降级实例标记 `Failed=true`，避免诊断把空模块算作真实模块；注册战斗、子弹与阵营缓存状态。
- **SCP**：注册角色、候选扫描帧数和模块失败数量诊断。
- **版本**：Loader 2.10.0，runtime manifest 同步更新；生成全部 12 个构建产物。

## 来源与范围

已检查上传的 Forsaken、BloxStrike、AOTR 参考源码的角色监听、Heartbeat、场景对象和远程接口惯用方式；采用现有项目架构独立实现，未批量复制引用脚本。SCP 参考文本也用于此前兼容性审计。

## 验证

- 当前维护的 Python/Lua 5.4 Mock 单元与结构测试：97 项通过。
- R2.10 新增跨游戏状态测试：6 项，包括真正执行桥接的模拟状态核对。
- `python3 build.py`：6 个单包 + 1 个共享核心 + 5 个游戏模块构建通过。
- `python3 verify_release.py`：12 个产物 SHA-256 和大小通过。
- `git diff --check`：对改动文件执行空白检查。

## 已知限制

- **没有 Roblox Android 真机验证**：不能证明每个玩法接口、命中、发电机修理、皮肤替换等服务器端效果已经恢复。
- 1Hz 状态同步只处理原生 Toggle 最终状态与桥接值不一致；如果原生控件值与业务值一致但游戏服务器拒绝效果，它不会伪装成成功。
- 历史 `test_forsaken_wind.py` / `test_wind_migration.py` 依赖 R2.5 已删除的文件，不能导入，未计入有效测试。
- 部署脚本只接受当前已核对的 GitHub `main` 提交。远程仓库更新则停止，避免覆盖他人更新。

## 实机复测

1. 进入游戏，在 `UI → 调试` 使用「跨游戏回调状态复核」并观察修复数和健康状态。
2. Forsaken 活着/死亡/观战/重生各测一次视觉开关；诊断查看 UI/Bridge/Runtime、Refresh/Markers/模式。
3. AOTR 战斗看巨人池、Combat/ESP 初始化状态；大厅看角色和 FOV 状态。
4. BloxStrike 看 Combat/Bullet 是否为 ready；SCP 看 Candidates.Frame 是否增长。
5. 对服务器权限或版本变化引发的真实玩法失败，仍需要额外日志和游戏内实际状态验证。
