# Vortexion R2 · 运行缺陷修复与功能增强

## 本轮范围

本轮基于 R1 `Vortexion_R1_Refactor_Source.zip`，聚焦加载、分游戏启动状态、BloxStrike 外观 UI、SCP 兼容降级、AOTR 子模块隔离及共享性能 HUD。**未引入参考压缩包中的未经验证网络脚本，也未宣称完成全部玩法功能移植。**

## 已修改（源代码级）

1. **Loader 2.2**：修复失败重试误删已验证会话缓存。首次下载但本次失败的核心/模块仍被剔除；复用过的旧缓存保留。修复后 `Retry` 可重用上一轮已验证的核心，避免无意义重复下载。
2. **统一路由 `GameRouter`**：保留游戏模块主动设置的 `BootStatus=partial` 和 `BootError`，不再因窗口存在就将“部分失败”覆盖为“启动成功”。
3. **BloxStrike**：各模块工厂缺失/抛异常时聚合启动错误供加载器识别；皮肤目录延迟复制、类别新增时自动重新扫描；已有皮肤下拉可使用 `SetValues` 增量更新；下拉创建失败允许下一次刷新重试；恢复默认皮肤时同步更新 UI 开关；新增「皮肤资源状态」「子模块初始化诊断」。
4. **SCP**：模块工厂缺失/报错不再被当作完整成功；Cloak 模块不可用时 `Protect` 降级为返回原对象，避免依赖层被注入 `nil`；新增「子模块初始化诊断」。
5. **AOTR 战斗**：Cloak 工厂异常不再导致所有功能在创建 tabs 之前退出；其他子模块的错误也会标记为部分失败；新增初始化诊断按钮；Common 不可用时直接退出并交给路由兜底。
6. **通用性能 HUD**：新增平均帧耗时、峰值帧耗时、≥50ms 卡顿帧计数和采样重置；无效 `dt` / NaN 采样间隔不会污染统计。该监测仍为用户显式启用，关闭则释放 Heartbeat 监听。

## 验证等级

- Python unittest 全量现行门禁：`47` 个测试通过（含 Lua5.4 mock 的部分测试及 R2 新增回归）；不等同于原生 Roblox Luau 编译或真机验证。
- `python3 -B build.py`：六个旧兼容包 + 六个模块化代码产物生成，清单与源文件对应。
- `python3 verify_release.py`：13 个发行文件哈希/长度校验通过。
- 未进行 Roblox 安卓运行、执行器 API、服务器侧玩法有效性、FPS 提升量验证。
- WindUI 第三方 vendor 未修改；并不宣称本轮完成全项目全面重构。

## 风险与待实测清单

- BloxStrike 当前服务器如修改 `Assets/Skins` 节点名称、资源类型或生命周期，下拉项需要根据现场对象树再适配。现有事件驱动只在资源变化时更新，**不提供强制等待或后台高频扫描**。
- SCP / AOTR 部分模块依赖特定游戏版本、执行器能力及服务器规则，当前只能验证异常隔离，不能断言实际射击/战斗能力。
- HUD 仅是客户端采样；`Ping` 与 `Stats` 有平台依赖，缺失时显示 `--`，不卡住启动。
- R1 增量包曾未远程部署，本次提供 **R1+R2 全量快照** 以避免缺失依赖。

## 推荐验证流程（安卓实测）

先运行统一 loader，检查：游戏识别结果、各子模块初始化诊断、皮肤页面是否有武器类别、禁用后贴图是否恢复、重新执行后无旧窗口残留、性能 HUD 停用后消失。对于任何失败复制诊断文本记录 GameId、PlaceId、阶段、错误；不要上传私有会话令牌。
