# Vortexion R2.5 — Forsaken 精简与 AOTR 战斗启动降风险

## 用户问题
- Forsaken「全部功能失效」、选项过多、部分开关无效；旧核心包含大量角色专用远程、第三方 URL、动作替换与周期性监听。
- AOTR 战斗加载时客户端闪退。当前无设备崩溃日志，因此只能确认源码风险，不能从静态检查断定闪退唯一原因。

## 修改范围

### Forsaken（实质重构）
- 用约 10KB 的轻量核心代替约 150KB 的旧核心；构建不再注入四组附加工厂（旧四个 `src/Forsaken*.luau` 功能组从活动仓库移除）。
- 7 个一级分页精简为：感知、角色、系统（3 页）。
- 感知：杀手/幸存者高亮、发电机高亮、附近杀手预警及各自距离调节。
- 角色：相机 FOV（60–120），关闭还原进入前的原始相机 FOV。
- 系统：场景结构自检（Killers、Survivors、当前标记、刷新计数、最后错误）、重进当前游戏、卸载功能。
- 用户明确开启时才创建最多一个 Heartbeat 监听；0.25 秒最小刷新间隔，最多 32 个标记；关闭立即断开、删除全部标记；重进执行时先清理前一实例。
- **删除** 外部动态加载脚本、无法确认适配的远程攻击功能、重复 ESP 子系统、独立快捷弹窗、背景视频、旧音频/动作触发、大量未知角色专用功能；保留的旧资产可能仍作为归档文件存在，但不被初始化。

### AOTR 战斗（启动保护）
- 不再打包与调用 `AOTRCloakFactory`，阻止在启动时安装全局 `__namecall`/元方法钩子；保留兼容的空操作 `Protect` 接口供 ESP 使用。
- HUD/Remotes 提前扫描不再阻塞窗口启动；远程对象以 deferred 方式探测，HUD 按需读取。
- 当战斗 / ESP / 跟随 / 资源自动化全部关闭时，跳过巨人扫描、战斗与绘制工作，降低空闲帧负载。
- 原有战斗玩法接口保持，不在本轮重写攻击协议。

## 验证边界
- Python 构建、完整性：12/12 产物校验通过。
- R2.5 专项：6/6（Lua 5.4 对部分 Luau 语法作等价转换，仅模拟 Roblox 信号/界面）通过；旧 R2.4 主题测试 3/3、R2.3 原始异常测试 3/3 通过。
- **未** 在 Roblox Android 真机证明高亮一定可见、当前游戏的文件夹路径一定存在，亦未证明 AOTR 闪退彻底消除。移除危险初始化是降低崩溃风险，不是设备侧根因认定。
- 仓库旧测试中依赖已经删除的 Forsaken 旧功能 ID 与 AOTR Cloak 的断言已不再适用；不得将旧测试失败算作新功能通过。

## 真机验收顺序
1. 更新 GitHub `main`，重新进入 Roblox，执行 `loader.lua`，检查 Loader 显示的 Build Tag 含 `r2.5`。
2. Forsaken：打开 UI，确认 3 页；先测试 FOV 变更及恢复，再打开杀手/幸存者 ESP 和预警；在 UI「检查游戏结构」看是否识别到对应游戏文件夹。
3. AOTR 战斗：先不启用任何选项观察是否仍闪退；再逐个启用感知、移动、战斗；若仍闪退，收集执行器名、系统版本、崩溃前最后日志及时间点。
